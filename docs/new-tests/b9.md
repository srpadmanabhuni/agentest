NT-050 to NT-052 are opt-in. They read recorded OpenTelemetry traces, the agent's MCP tool descriptors and team-declared fields. They are not in the default run, so existing checks and their verdicts do not change. They are not part of the published test count of 165.

## NT-050 No tool-call cycle repeats with no new result

Reads: tool spans (`gen_ai.tool.name`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`, error status), ordered by start time.

- Pass: no pattern of two to four different calls (same tool and same arguments) repeats three times in a row with identical results every time.
- Fail: such a cycle is found. The detail names the calls and the repeat count.
- n/a: no run has six or more tool calls.

X-004 judges one call repeated. A call whose result changes between repeats, such as polling a job until it finishes, is progress and is not a cycle.

Known limits:

- Only consecutive repeats are found. A cycle with other calls between its turns is not.
- Calls that differ in a single argument (a timestamp, a nonce) are different calls, so a cycle that varies such an argument is missed.
- Results are compared as recorded text, so a result that embeds a changing timestamp hides a cycle.
- The thresholds (three repeats, patterns of two to four calls) are fixed in code.

## NT-051 Tool-call arguments satisfy the declared input schema

Reads: `gen_ai.tool.call.arguments` on each tool span and the `inputSchema` of the tool in the agent's MCP `tools.json`.

The schema subset: `type`, `required`, `properties`, `additionalProperties: false`, `items`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `minLength`, `maxLength`, `minItems` and `maxItems`, to a nesting depth of six.

- Pass: every judged call satisfies the schema subset.
- Fail: a call breaks it, or its recorded arguments are not a JSON object. The detail names the tool and the first two problems.
- n/a: no call can be judged. A call is judged when its arguments were recorded and its tool declares an `inputSchema` with `properties` or `required` keys.

Known limits:

- `enum` values are T5-003. `pattern`, `format`, `$ref` and the combinators (`allOf`, `anyOf`, `oneOf`) are not evaluated, so a schema that relies on them is only partly checked.
- Every call is judged, including one the tool then rejected. A call that failed validation and was then corrected still counts as a failure of the first call.
- A trace that does not record the arguments is `n/a` for that call. Recorded empty arguments (`{}`) are judged and fail when the schema requires keys.
- Keys that the schema does not declare are allowed unless the schema sets `additionalProperties` to false, as JSON Schema does.

## NT-052 A refusal reply does not follow a successful state change

Reads: `agentest.output.refused`, `agentest.task.refusal_exempt_tools` (a list or comma-separated names), the reply text, tool spans with the MCP `readOnlyHint` annotation, and executed state-change events.

- Pass: no judged run has a successful state-changing tool call or an executed effect, other than tools listed in `agentest.task.refusal_exempt_tools`.
- Fail: a judged run has one. The detail names the tool or the number of executed effects.
- n/a: no run has a refusal reply.

A run is judged when its reply is a refusal and, when `agentest.output.refused` is not recorded, no clause of the reply also reports that something was done. A tool that refused in its own result does not count as a state change. T7-009 judges the opposite direction, a completion claim with no action.

Known limits:

- The refusal wording is an uncalibrated English heuristic, and so is the completion wording used to set aside partial refusals.
- A refusal that follows a legitimate side effect, such as opening a ticket to escalate, fails unless the tool is listed in `agentest.task.refusal_exempt_tools`.
- A write whose purpose was unrelated to the refused request fails too, because the check cannot tell which request a write served.
- A write that fails without an error status on the span is counted as successful.

All three checks are opt-in and do not change default verdicts or the published test count of 165.
