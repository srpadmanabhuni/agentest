# New tests NT-041, NT-042 and NT-043

These three New tests are opt-in. They read recorded OpenTelemetry traces and team-declared fields. They are not in the default run, so existing checks and their verdicts do not change. They are not part of the published test count.

```bash
agentest std run --ids NT-041,NT-042,NT-043
```

A missing declaration is `n/a`, never `pass`. List attributes may be OTLP string arrays, JSON lists or comma-separated strings. Repeated runs of one task are grouped by `agentest.task.id`, otherwise by `agentest.input.id`, the same grouping the earlier per-task checks use.

| ID | Check | Article test |
|:--|:--|:--|
| NT-041 | Trials of one task start from a clean environment | A022 Autonomy Test Environment Fidelity |
| NT-042 | All trials of a consistency-critical task succeed | A001 Task Success Rate |
| NT-043 | Tool errors and repeated calls stay within the declared budget | A002 Execution Efficiency |

## NT-041 Trials of one task start from a clean environment

Reads: `agentest.task.initial_state` on the root span; spans named `agentest.environment.change` (or any span carrying `agentest.environment.change.ref`) with `.kind` and `.ref`.

- The declared start state is `agentest.task.initial_state`. Every trial of the task must declare that same value.
- An earlier trial writes an artefact when its change kind is `write`, `create`, `update`, `put` or `produce` (or the kind is omitted and the ref has not been written yet).
- A later trial reads it when the kind is `read`, `get`, `load`, `fetch`, `consume` or `open`, or when the kind is omitted and an earlier trial already wrote that ref.
- A trial may read an artefact it wrote itself. A later write of a different ref is not a read.
- n/a: no trial declares an initial state.

`agentest.environment.change` is also listed under Planned for 1.1 because it is not in the 1.0.0 schema yet. This check reads the span when it is present. Unknown attributes stay allowed.

## NT-042 All trials of a consistency-critical task succeed

Reads: the AgentCard skill field `consistency_required` (a positive integer `k`, or `{"k": k}`); trials linked to that skill; the same postconditions the outcome checks use (`gen_ai.evaluation.result`, and in examples mode the published postconditions).

- A trial is linked when `agentest.task.skill` is the skill id, or, if that attribute is absent, when `agentest.task.id` is the skill id, or when the user input matches a skill example.
- Pass: at least `k` linked trials are recorded and every one of them meets its postconditions (pass^k).
- Fail: fewer than `k` trials are recorded, or any linked trial does not meet its postconditions.
- n/a: no skill declares `consistency_required` with `k`, or no trial is linked to such a skill.

This complements T1-003, which compares a success rate with a threshold. A rate can pass while one trial still fails; NT-042 does not.

`consistency_required` is ignored when it is absent. Other checks do not read it.

## NT-043 Tool errors and repeated calls stay within the declared budget

Reads: `agentest.task.budget.tool_errors` and `agentest.task.budget.repeat_calls` on the root span; tool spans (`error.type`, error status, `gen_ai.tool.name`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`).

Counts are pooled across the trials of one task.

- A tool error is a tool span with `error.type` or an error status, or a result that says the arguments are invalid. A JSON error code `-32602` counts as an invalid-argument result. One span counts once.
- A repeated call is an identical `(name, arguments)` call after the first of that pair. The first call is not a repeat.
- Each budget is checked only when that budget is declared. Trials that declare different numbers for the same budget fail.
- n/a: neither budget is declared.

Recording rejected calls from a proxy log is a separate example. This check only counts what the trace already contains.
