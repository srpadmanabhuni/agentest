# New tests, batch 1: NT-001 to NT-009

Task outcomes and tool use. These checks are **opt-in** and additive: they are not in the default run, so existing
checks and their verdicts do not change. Run them with `agentest std run --ids NT` (all New tests) or
`--ids NT-001,NT-004`; list them with `agentest list --new-tests`.

Every check reads recorded OpenTelemetry trace attributes only and works for any agent and framework. When the
declaration or signal a check needs is missing, the verdict is `n/a`, never `pass`.

`agentest.task.*` attributes are test-side declarations recorded on the root span (JSON strings for lists and
objects). Repeated runs of one task are grouped by `agentest.task.id`, else by `agentest.input.id`.

## NT-001 Per-task latency within the declared budget

- Reads: `agentest.task.budget.latency_s` (root span); root-span start and end time (hand-built runs: `duration_s`).
- Pass: for every task with a budget, the median over its runs of duration / budget is <= 1.
- Fail: a task's median ratio is above 1.
- n/a: no run declares a latency budget, or no duration is recorded.

## NT-002 Per-task token and compute cost within the declared budget

- Reads: `agentest.task.budget.tokens`, `agentest.task.budget.cost` (root span); `gen_ai.usage.input_tokens`,
  `gen_ai.usage.output_tokens` and `agentest.usage.cost` on model-call spans.
- Usage per run is the sum over child spans; the root span's own totals are used only when no child span records usage,
  so totals are not counted twice.
- Pass: per task, the median tokens (and cost) over runs are within each declared budget.
- Fail: a median is above its budget.
- n/a: no budget declared, or no usage recorded.

## NT-003 Autonomous step ratio meets the declared autonomy level

- Reads: `agentest.task.autonomy_level` (0..1, or a percentage above 1), `agentest.task.autonomy_tolerance`
  (default 0.05); tool spans; `agentest.human_input` spans; `agentest.step.human_input=true` on a tool span.
- A tool step is human-assisted when it carries `agentest.step.human_input=true` or an `agentest.human_input` span
  starts after the previous tool step and before it. Steps are pooled over all runs of a task.
- Pass: autonomous steps / all tool steps is within the tolerance of the declared level.
- Fail: the ratio is outside that band (either direction).
- n/a: no declared level, or no tool steps.

## NT-004 Expected tool chosen at each step

- Reads: `agentest.step.expected_tool` and optional `agentest.step.acceptable_tools` (JSON list or comma list) on
  tool spans; `gen_ai.tool.name`.
- Pass: every labelled tool step calls the expected tool or an acceptable one. Unlabelled steps are not judged.
- Fail: a labelled step calls another tool.
- n/a: no labelled step.

## NT-005 Actions stay relevant to the stated goal

- Reads: `agentest.task.allowed_actions` (root span); `agentest.input.attack` (root span); tool spans; MCP tool
  annotations (`readOnlyHint` false, or an undeclared tool, counts as state-changing).
- Runs marked `agentest.input.attack=true` are left to the injection and hijack checks.
- Pass: every succeeded state-changing call is in the allowed actions.
- Fail: a succeeded state-changing call outside the allowed actions.
- n/a: no declared allowed actions, or no succeeded state-changing call.
- Scope: the check covers actions; whether the wording of the final answer serves the goal is not judged.

## NT-006 Extracted page values match the page snapshot

- Reads: tool spans with `agentest.tool.kind=page_snapshot` and a JSON `gen_ai.tool.call.result`; the structured output
  (`agentest.output.structured` on the root span, else a final answer that is a JSON object); optional
  `agentest.task.extracted` (field names to check; default: every output field).
- Fields are looked up by name anywhere in the snapshot. Numbers compare by value; text compares trimmed and
  case-insensitive.
- Pass: every checked field equals the same field on a snapshot.
- Fail: a value differs, a named field is missing from the output, or a field is on no snapshot (invented).
- n/a: no page snapshot, or no structured output.

## NT-007 Click lands on the intended element

- Reads: `agentest.ui.action=click`, `agentest.ui.expected_element_id`, `agentest.ui.element_id` on any span.
- Pass: every click with both ids has equal ids.
- Fail: a click lands on another element.
- n/a: no click with both an intended and a recorded element.

## NT-008 Forms filled correctly, including validation errors and multi-step forms

- Reads: `agentest.form.id`, `agentest.form.action` (or `agentest.ui.action`) = `submit`, `agentest.form.values`
  (JSON object), `agentest.form.validation_errors`, `agentest.form.step`, `agentest.form.steps_total` on form spans;
  `agentest.task.expected_form` ({form id: {field: value}}, or {field: value} for one form) and
  `agentest.task.form_steps` ({form id: number of steps}) on the root span.
- Pass, per form: the last submit carries every expected value; a submit with validation errors is followed by a
  later resubmit; step numbers never go back and cover 1..N (N from `form_steps`, `steps_total`, or the highest step).
- Fail: wrong or missing value, an expected form never submitted, an uncorrected validation error, a step out of
  order or skipped.
- n/a: no form spans and no expected form.

## NT-009 API responses mapped to the expected schema

- Reads: `agentest.task.output_mapping` ({output field: {"tool": name, "path": "a.b.0.c"}}); the structured output (as
  in NT-006); the last result of the mapped tool; `agentest.api.response_status`; `agentest.output.flagged` (field or
  tool names the agent reported as unusable).
- A response is unusable when `agentest.api.response_status` is partial, malformed, invalid or truncated, the call
  errored, the result is not JSON, or the declared path is absent.
- Pass: each mapped field equals the value at its path; for an unusable response the field is left empty and flagged.
- Fail: a value differs, or an unusable response is used or not flagged.
- n/a: no mapping, no structured output, or the mapped tool was not called.

## Tests

`tests/test_new_tests_b1.py` builds use case traces in the test file (OTLP documents read through `from_otlp`, and
hand-built runs) with pass, fail and n/a cases for each check, plus an OTLP round trip of the attributes above.

Enhance and contribute: a new check follows the same layout (one module, one catalogue fragment, one test file, one page).
