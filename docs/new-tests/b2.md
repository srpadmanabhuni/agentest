## Agent-to-agent message spans (NT-010, NT-011, NT-012)

Any span can carry one agent-to-agent message:

| Attribute | Meaning |
|:--|:--|
| `agentest.a2a.message_id` | Message id, the same on the sending and the receiving span |
| `agentest.a2a.direction` | `send` or `receive` (if absent, a span name ending in `.send` / `.receive` is used) |
| `agentest.a2a.payload` | The payload (JSON or text) |
| `agentest.a2a.payload_hash` | sha256 hex of the payload (optional `sha256:` prefix), when the payload itself is not recorded |
| `agentest.a2a.transform` | Declared, intended change on this hop (any non-empty value) |
| `agentest.a2a.message_type` | Handover message type, e.g. `request`, `accept`, `result`, `subgoal` |
| `agentest.a2a.fields` | Handover fields as a JSON object (falls back to a JSON-object payload) |
| `agentest.a2a.ack_of` | On an acknowledgement span: the message id it acknowledges |

**NT-010.** For every message id with a send span and at least one receive span, the payload must be unchanged. When
both spans carry `payload_hash` the hashes are compared (case-insensitive); otherwise the sha256 of the canonical
payload (JSON with sorted keys and no spaces; plain text as is) is compared with the other side's payload or hash.
A hop with `agentest.a2a.transform` is accepted. n/a: no message with a comparable send and receive.

**NT-011.** Declare `agentest.task.handover_schema`:

```json
{"message_types": ["request", "accept", "result"],
 "required": {"*": ["task_id"], "result": ["task_id", "outcome"]},
 "order": ["request", "accept", "result"]}
```

`required` is a list (all types) or a map from type to fields (`*` = default). Handover messages are the spans with
`agentest.a2a.message_type` (the send side when directions are recorded). Each must use an allowed type, have every
required field non-empty, and types listed in `order` must not go back to an earlier step. n/a: no schema or no
handover message.

**NT-012.** Declare `agentest.task.ack_within_s`. Each sent message of type `subgoal` needs an acknowledgement span
(`agentest.a2a.ack_of` = its message id) starting within that many seconds. A sub-goal with no acknowledgement
when the trace ended before the bound cannot be judged and does not count. n/a: no bound or no judgeable sub-goal.

## Autonomy limits and windows (NT-013, NT-014)

Human input is a span named `agentest.human_input` or `agentest.approval`, or any span with
`agentest.step.human_input=true`. A handoff or stop is a span named `agentest.handoff` or `agentest.stop`, a span
with `agentest.handoff.source`, a message of type `handoff` / `escalation`, or `agentest.step.kind` =
`handoff`, `stop` or `escalate`. A tool call is a span with `gen_ai.operation.name=execute_tool`.

**NT-013.** Declare `agentest.task.limits`, e.g. `{"tool_calls": 3, "steps": 10, "spend": 1.0, "scope": ["search"]}`.
`steps` counts model and tool spans (`chat`, `text_completion`, `generate_content`, `execute_tool`); `spend` sums
`agentest.usage.cost` on any span; `scope` is reached by the first tool call outside the listed tools. At the span
where each limit is first reached, the next action (tool call, human input, handoff or stop) must not be a tool
call; the run ending there also passes. Counting continues after human input, but each limit is judged once per
run. n/a: no limits, or no limit reached.

**NT-014.** Declare `agentest.task.autonomy_window_s` and optionally `agentest.task.autonomy_window_tolerance_s`
(default 0). The window starts at the root span start. A tool call starting after window + tolerance fails unless
human input came after the window ends and before that call. n/a: no window, or the run ended inside window +
tolerance.

## Step-up authorisation (NT-027)

Declare the high-impact tools in `agentest.task.step_up_tools` (list) and/or the governance extension
`approval.stepUp` (both are used). Each succeeded call to one of these tools needs its own earlier `agentest.approval`
span with `agentest.approval.granted=true`, `agentest.approval.action` equal to the tool name and
`agentest.approval.kind` of `step_up`, `mfa` or `second_factor` (`step-up` is accepted). One step-up approval covers
one call. Failed (errored) calls do not count. n/a: no step-up tools declared, or no succeeded call to one.
