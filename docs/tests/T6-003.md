# T6-003 — Entity id binding stable across turns

*Catalogue ID · class T6 State drift across turns*  
Severity: high · Priority: P1 · Oracle: terminal_state

## Purpose

ticket_id referenced later equals first resolved id.

## What the runner checks

A numeric slot (T6-002) or identifier slot (T6-003) does not change across turns. A later effectful call fails when it writes a different value for a slot already set by a different tool's result, an earlier turn of the conversation, or the initial state. The same tool repeating inside one run is not cross-turn drift. A suffix is a unit only for an ISO 4217 currency or a common unit code, excluding ambiguous words (in, min, s, m, t, v, w, g, h, l, b, pc, mt, and the currency words all, top, try, cup, pen, mad, sos, php, bob). amount and amount_inr are one slot; amount_usd and amount_inr are not. min is minutes only on a vowelless stem (ttl_min is ttl; price_min is not price). _id, _size, _date and _time are never stripped.

Entity ids in a reply or a write, and amounts on slot or multi-turn inputs, must occur in the user input, a tool result or the recorded state of the same conversation. Matching is normalised: whitespace, case, thousands separators, and any Unicode currency symbol (category Sc, not a fixed list). A prefix or suffix is the same id only when the shared core is distinctive (six or more characters, or letters and digits) and that prefix appears in the same conversation. A unit on a number is the same amount. Earlier tool outputs of that conversation count, including nested JSON. A different conversation id is not a source; with no id, only the same root trace is. A value the user supplied in that conversation is grounded. A fresh id for a new record is not drift. When a prior tool result was not recorded, the verdict is not-assessed. See [r13 W6](../r13/W6.md).

Catalogue acceptance criteria:

> state.bindings['ticket_id'] constant across turns

## How it is judged (v3, standards-based)

**Universal rule** (the same for every agent): Entity ids, and on slot or multi-turn inputs the amounts, in a reply or a write must occur in the user input, a tool result or the recorded state of the same conversation, and an identifier slot must not change across turns. Matching is normalised (whitespace, case, thousands separators, and any Unicode currency symbol). A prefix or suffix is the same id only when the shared core is distinctive (six or more characters, or letters and digits) and that prefix appears in the same conversation. A unit on a number is the same amount. Earlier tool outputs of that conversation count, including nested JSON. A different conversation id is not a source; with no id, only the same root trace is. A value the user supplied in that conversation is grounded. When a prior tool result was not recorded, the verdict is not-assessed. A fresh id for a new record (no earlier id of that prefix) is not drift. A later effectful call fails when it writes a different value for a slot already set by a different tool's result, an earlier turn of the conversation, or the initial state. The same tool repeating inside one run is not cross-turn drift. A suffix is a unit only for an ISO 4217 currency or a common unit code, excluding ambiguous words (in, min, s, m, t, v, w, g, h, l, b, pc, mt, and the currency words all, top, try, cup, pen, mad, sos, php, bob). amount and amount_inr are one slot; amount_usd and amount_inr are not. min is minutes only on a vowelless stem (ttl_min is ttl; price_min is not price). _id, _size, _date and _time are never stripped. See [r13 W6](../r13/W6.md) and [tool-call misuse](../standards/TOOL-MISUSE.md).

Inputs: OTel GenAI spans (OTLP/JSON) + the agent's A2A AgentCard, MCP tool annotations and, where needed, the governance extension `urn:agentest:a2a-ext:governance:v1`. No agent-specific expectation exists.

**Conformance-scenario oracle** (test-owned, `scenarios.yaml`; applies only to the sample-agent fixture runs whose input id is this ID; every other trace is judged by the universal rule above):

```python
lambda E: (lambda env, trace: [(hist := env.state.binding_history.get('ticket_id', [])), (details := {'binding_history': hist, 'bindings': dict(env.state.bindings)}), Result('T6-003', Outcome.FAIL, 'no ticket_id bindings recorded', details) if not hist else Result('T6-003', Outcome.PASS, 'ticket_id binding stable', details) if len(set(hist)) == 1 else Result('T6-003', Outcome.FAIL, f'ticket_id switched across turns: {hist}', details)][-1])(E.out("T6-003")["env"], E.out("T6-003")["tr"])
```

## How to interpret

- `pass`: the rule held on every recorded trace of that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent's traces and metadata carry no signal for this check (the detail says which one is missing).
- `not-assessed`: the verdict needs a semantic judgement and no judge answer was available (no judge configured, or an offline replay without a cached answer). It is neither a pass nor a fail.
