# T2-009 — Independent siblings may interleave

*Catalogue ID · class T2 Dependency ordering*  
Severity: medium · Priority: P2 · Oracle: tool_trace

## Purpose

topo valid allowing concurrent siblings.

## What the runner checks

Independent siblings may interleave but the summary step runs only after the inputs it depends on.

Catalogue acceptance criteria:

> write_summary only after both fetches done

## Preconditions

- `pip install -e ".[dev]"`; no network, no API key, no model needed for replay.
- Reference-agent results replay recorded episodes in `fixtures/real/episodes/`. Re-recording needs the local 7B GGUF (see GUIDEBOOK.md, Recording).

## How it is judged (v2, model-driven)

Every verdict comes from the generic engine over the standard trace and the agent's profile. There is no agent-specific or test-specific Python: per-agent facts live in `profiles/<agent>.yaml`, shared expectations in `profiles/_lib/*.yaml`.

**Sample agents (15):** expectation from `profiles/_lib/samples.yaml`, evaluated over the recorded scenario snapshot:

```python
lambda E: (lambda env, trace: [(_tu0 := tuple(t2__check_depends(trace, T2_009_GRAPH))), (ok := _tu0[0]), (msg := _tu0[1]), (details := {'calls': [c.name for c in trace.calls]}), Result('T2-009', Outcome.PASS, 'sibling graph topo ok', details) if ok else Result('T2-009', Outcome.FAIL, msg, details)][-1])(E.out("T2-009")["env"], E.out("T2-009")["tr"])
```

Method notes:

> T2-009 oracle: write_summary only after both sibling fetches (fetch_profile, fetch_prefs).
> 
> catalogue ID(s): T2-009
> 
> Algorithm (step by step):
> 1. Walk trace.tool_calls in order, maintaining the set of tools that succeeded so far.
> 2. For each call, look up its prerequisite set in the DEPENDS_ON graph (thresholds.py).
> 3. If any prerequisite has not yet succeeded -> FAIL with the missing edge.
> 4. If the whole trace is walked without violation -> PASS (trace is a valid linearisation / topological order of the graph).
> 
> Thresholds / rationale: Graph T2_009_GRAPH; siblings may run in any order.
> 
> Pass / fail interpretation: PASS = any valid topological order is accepted.
> 
> Limitations: Order only.
> 
> Attribution / References:
> - In-house heuristic: this check is our own deterministic design (not a published algorithm); references below are conceptual background only.
> - Kahn, A. B. (1962). Topological sorting of large networks. Communications of the ACM 5(11):558-562. https://doi.org/10.1145/368996.369025
> - Catalogue mapping (test-ID source only, not the source of the method above): Padmanabhuni, S. (2026). Agentic AI Assurance Test Taxonomy v1. Zenodo. https://doi.org/10.5281/zenodo.23587407

## How to interpret

- `pass`: the oracle held on every recorded episode for that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent has no surface for this check (or a translation-fidelity gate tripped).
