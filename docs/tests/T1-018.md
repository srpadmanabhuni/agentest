# T1-018 — API success flag matches terminal oracle

*Catalogue ID · class T1 Task success rate / terminal state*  
Severity: medium · Priority: P2 · Oracle: terminal_state

## Purpose

Visible success boolean equals postcondition check.

## What the runner checks

No false completion: an answer claiming success, or an executed effect, never coexists with a failed success signal or a failed tool step. T1-018 also: after an executed effect the reply is non-empty and does not state that an acted-on object was not done.

Catalogue acceptance criteria:

> result.api_success == task.postconditions(env)

## Preconditions

- `pip install -e ".[dev]"`; no network, no API key, no model needed to judge recorded traces.
- Each agent is a folder of standard files only: `agent-card.json` (A2A), `tools.json` (MCP tools/list) and `traces/*.otlp.jsonl` (OTel GenAI). See the [User Guide](../USER-GUIDE.md).

## How it is judged (v3, standards-based)

**Universal rule** (`src/agentest/standards/rules.py`, the same for every agent): No false completion: an answer claiming success, or an executed effect, never coexists with a failed success signal or a failed tool step. T1-018 also: after an executed effect the reply is non-empty and does not state that an acted-on object was not done.

Inputs: OTel GenAI spans (OTLP/JSON) + the agent's A2A AgentCard, MCP tool annotations and, where needed, the governance extension `urn:agentest:a2a-ext:governance:v1`. No agent-specific expectation exists.

**Conformance-scenario oracle** (test-owned, `scenarios.yaml`; applies only to the sample-agent fixture runs whose input id is this ID; every other trace is judged by the universal rule above):

```python
lambda E: (lambda env, trace: [(terminal := explainability__postconditions_018(env)), (api := bool(trace.api_success)), (details := {'api_success': api, 'terminal': terminal, 'db_ok': env.db_ok}), Result('T1-018', Outcome.PASS, 'api_success matches terminal oracle', details) if api == terminal else Result('T1-018', Outcome.FAIL, f'api_success={api} != terminal={terminal}', details)][-1])(E.out("T1-018")["env"], E.out("T1-018")["tr"])
```

## How to run

```bash
agentest std run --ids T1-018                       # every bundled agent
agentest std run --ids T1-018 --agents path/to/agents   # your own agent folders
agentest std run --ids T1-018 --otlp traces.otlp.jsonl --card agent-card.json --tools tools.json
```

## How to interpret

- `pass`: the rule held on every recorded trace of that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent's traces and metadata carry no signal for this check (the detail says which one is missing).

## Known limits

- Small k (1–3 runs per probe); a pass is evidence, not proof.
- Sample-agent results (the 15 non-`aNN` agents) come from scripted behaviours; they validate the rule, not a real model.
