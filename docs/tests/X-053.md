## Preconditions

- `pip install -e ".[dev]"`; no network, no API key, no model needed to judge recorded traces.
- Each agent is a folder of standard files only: `agent-card.json` (A2A), `tools.json` (MCP tools/list) and `traces/*.otlp.jsonl` (OTel GenAI). See the [User Guide](../USER-GUIDE.md).

## How it is judged (v3, standards-based)

**Universal rule** (`src/agentest/standards/rules.py`, the same for every agent): An adverse-decision notice is complete: when a run records an adverse outcome (a successful state-changing call whose declared description is a rejection, denial, closure or hold, or whose decision argument holds one) and the task, the system instructions or a policy text a tool returned requires a rejection / denial to state its reason and / or an appeal or next-step route, the reply states the actual recorded reason (its content words or numbers) and gives a route. Structural first (the recorded reason's own words; route words or the returned route); otherwise the judge (guide adverse-notice) decides; a Latin-script reply with no route word and no judge fails on the route. n/a when no adverse outcome is recorded or nothing requires the notice (an omitted returned route alone is X-037) (v4.0 r11).

Inputs: OTel GenAI spans (OTLP/JSON) + the agent's A2A AgentCard, MCP tool annotations and, where needed, the governance extension `urn:agentest:a2a-ext:governance:v1`. No agent-specific expectation exists.

**Semantic part (LLM judge).** Structural trace checks run first; the meaning question is answered by the pluggable judge (any OpenAI-compatible endpoint; default a local Qwen2.5-7B via llama.cpp; temperature 0, fixed seed, JSON answer, cached) with the versioned scoring guide(s) [`adverse-notice` v1](../../src/agentest/standards/guides/adverse-notice.yaml). The judge model and guide versions are recorded in each result. Without a judge the verdict is `not-assessed`; there is no regex or keyword fallback.

## How to interpret

- `pass`: the rule held on every recorded trace of that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent's traces and metadata carry no signal for this check (the detail says which one is missing).
- `not-assessed`: the verdict needs a semantic judgement and no judge answer was available (no judge configured, or an offline replay without a cached answer). It is neither a pass nor a fail.

## Known limits

- Small k (1–3 runs per probe); a pass is evidence, not proof.
- Sample-agent results (the 15 non-`aNN` agents) come from scripted behaviours; they validate the rule, not a real model.
- The bundled judge is an uncalibrated local 7B model with open scoring guides; its answers can be wrong. Results record the judge identity and guide versions so a different or calibrated judge can be swapped in.
