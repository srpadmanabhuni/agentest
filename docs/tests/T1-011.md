# T1-011 — External notify exactly once on success

*Catalogue ID · class T1 Task success rate / terminal state*  
Severity: medium · Priority: P2 · Oracle: terminal_state

## Purpose

Notify mock fires once iff terminal success.

## What the runner checks

External notify exactly once: approved send -> exactly 1 email; rejected send -> 0.

Catalogue acceptance criteria:

> success → call_count==1; failure → 0

## Preconditions

- `pip install -e ".[dev]"`; no network, no API key, no model needed for replay.
- Reference-agent results replay recorded episodes in `fixtures/real/episodes/`. Re-recording needs the local 7B GGUF (see GUIDEBOOK.md, Recording).

## How it is judged (v2, model-driven)

Every verdict comes from the generic engine over the standard trace and the agent's profile. There is no agent-specific or test-specific Python: per-agent facts live in `profiles/<agent>.yaml`, shared expectations in `profiles/_lib/*.yaml`.

**Sample agents (15):** expectation from `profiles/_lib/samples.yaml`, evaluated over the recorded scenario snapshot:

```python
lambda E: (lambda env, trace: [(success := (env.users.get('user_7', {}).get('status') == ACTIVE)), (expected := (1 if success else 0)), (got := env.notify.call_count), (details := {'success': success, 'notify_count': got, 'expected': expected}), Result('T1-011', Outcome.PASS, 'notify count matches success', details) if got == expected else Result('T1-011', Outcome.FAIL, f'notify_count={got} want {expected}', details)][-1])(E.out("T1-011")["env"], E.out("T1-011")["tr"])
```

Method notes:

> T1-011 oracle: notification sent exactly once iff the activation succeeded.
> 
> catalogue ID(s): T1-011
> 
> Algorithm (step by step):
> 1. success = user_7.status == ACTIVE.
> 2. expected notify count = 1 if success else 0.
> 3. Compare with env.notify.call_count; equal -> PASS, else FAIL.
> 
> Thresholds / rationale: Exactly-once semantics: 0 on failure, 1 on success, never duplicates.
> 
> Pass / fail interpretation: FAIL = duplicate or spurious/missing notification.
> 
> Limitations: Counts calls on the simulated notifier only.
> 
> Attribution / References:
> - In-house heuristic: this check is our own deterministic design (not a published algorithm); references below are conceptual background only.

## How to interpret

- `pass`: the oracle held on every recorded episode for that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent has no surface for this check (or a translation-fidelity gate tripped).
