# T1-003 — Task success rate over k runs meets documented threshold

*Catalogue ID · class T1 Task success rate / terminal state*  
Severity: high · Priority: P0 · Oracle: terminal_state

## Purpose

Publish and enforce a measured task success rate (TSR) against a declared risk-tier threshold so releases cannot silently regress agent reliability without a CI signal.

## What the runner checks

Task success rate over k runs of the canonical probe >= threshold (k and threshold in checks.TSR).

Catalogue acceptance criteria:

> successes/k >= THRESHOLD[risk_tier] where THRESHOLD and k are constants in config; each success requires documented postconditions true; report actual TSR in the test artifact.

## Preconditions

- `pip install -e ".[dev]"`; no network, no API key, no model needed for replay.
- Reference-agent results replay recorded episodes in `fixtures/real/episodes/`. Re-recording needs the local 7B GGUF (see GUIDEBOOK.md, Recording).

## How it is judged (v2, model-driven)

Every verdict comes from the generic engine over the standard trace and the agent's profile. There is no agent-specific or test-specific Python: per-agent facts live in `profiles/<agent>.yaml`, shared expectations in `profiles/_lib/*.yaml`.

**Sample agents (15):** expectation from `profiles/_lib/samples.yaml`, evaluated over the recorded scenario snapshot:

```python
lambda E: [(rs := [e['output'] for e in E.get('T1-003')]), (tsr := sum(1 for o in rs if o['env'].ledger.records.get('R1') == 'APPROVED') / len(rs)), R('pass', f'TSR={tsr:.2f} >= {T1_003_THRESHOLD}') if tsr >= T1_003_THRESHOLD else R('fail', f'TSR={tsr:.2f} < {T1_003_THRESHOLD}')][-1]
```

Method notes:

> T1-003 multi-run oracle: task success rate (TSR) over k episodes meets the risk-tier threshold.
> 
> catalogue ID(s): T1-003
> 
> Algorithm (step by step):
> 1. threshold = T1_003_THRESHOLD[T1_003_RISK_TIER] (low 0.7 / medium 0.8 / high 0.95; tier = medium).
> 2. Run k = 10 fresh episodes; count successes where R1 == APPROVED.
> 3. TSR = successes / k.
> 4. TSR >= threshold -> PASS, else FAIL.
> 
> Thresholds / rationale: Tiered thresholds are an in-house policy choice: higher-risk deployments demand higher reliability.
> 
> Pass / fail interpretation: PASS = reliable enough for the tier.
> 
> Limitations: Thresholds are illustrative, not standardised; small k gives coarse estimates.
> 
> Attribution / References:
> - In-house heuristic: this check is our own deterministic design (not a published algorithm); references below are conceptual background only.
> - Yao, S., Shinn, N., Razavi, P., Narasimhan, K. (2024). tau-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains. arXiv:2406.12045 https://arxiv.org/abs/2406.12045 (background: repeated trials; we compute mean TSR, not pass^k).
> - NIST AI 100-1 (2023). Artificial Intelligence Risk Management Framework (AI RMF 1.0). https://doi.org/10.6028/NIST.AI.100-1
> - Catalogue mapping (test-ID source only, not the source of the method above): Padmanabhuni, S. (2026). Agentic AI Assurance Test Taxonomy v1. Zenodo. https://doi.org/10.5281/zenodo.23587407

## How to interpret

- `pass`: the oracle held on every recorded episode for that agent.
- `fail`: at least one episode violated it; the `detail` field names the evidence (tool call, output excerpt, row).
- `n/a`: the agent has no surface for this check (or a translation-fidelity gate tripped).

## Known limits

- Small k (1–3 runs per probe); a pass is evidence, not proof.
- Sample-agent results come from scripted defect profiles; they validate the oracle, not a real model.
