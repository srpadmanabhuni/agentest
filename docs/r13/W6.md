# r13 W6 — language and numeric grounding

Version note: unreleased work on the `r12-core47` line. It is not a tagged release and it is not published.

## What changed

T6-010, T6-002 and T6-003 are implemented in `src/agentest/standards/detectors/f8.py`. The rule registry binds those three catalogue ids to that module. The other checks are unchanged.

### Reply language (T6-010)

The script is the Unicode block with the most letters (Latin, Kannada, Devanagari, Bengali, Tamil, and the other blocks listed in the module). A Latin identifier inside a sentence does not hide that sentence's block.

- The block decides the result when it does not match the user's language. A Kannada user answered in the Kannada block passes with no judge. A Kannada user answered in another non-Latin block fails with no judge.
- The judge (scoring guide `language`) is asked only when the block is Latin, which many languages share, or when a declared policy allows a Latin transliteration and the reply is Latin. A judge answer whose language does not use the Latin block is ignored, so a Latin reply is not failed as Tamil.
- Declared transliteration policy, in order: the run attribute `agentest.language.policy`, the task spec key `language_policy`, governance `languagePolicy.allowLatinTransliteration`, or a BCP-47 tag with a `Latn` script subtag such as `kn-Latn`. When the policy allows it, the judge decides whether the Latin text is that language. When the policy denies it, a Latin reply to that user fails. When nothing is declared, a tagged run keeps the script rule (a Latin reply to a Kannada user fails) and an untagged Latin reply is left to the judge.
- No language tag and no judge answer is `not-assessed`. It is not a pass.

### Amounts and ids (T6-002, T6-003)

On the same runs as before (slot and multi-turn inputs for amounts; those runs or any write for ids):

- Every amount in a short write slot, and every entity id in a write, must occur in the user input, an earlier tool result, or the state recorded before the run (`agentest.initial_state`). The same value written another way (`480`, `INR 480`) counts as the same amount.
- A number inside a free-text reason (four words or more) is still not a slot. A new id whose prefix has not been seen is still a created record, not drift.
- A reply amount (a currency amount, or a bare number of 100 or more) and a reply id must occur in the input, a tool result, or the recorded state. An id this run just created may be repeated in the reply.

## What did not change

The catalogue ids, the 38-test assessable scope, aggregation, thresholds and the rule that a positive `n/a` is a miss are unchanged. A missing judge is still `not-assessed`, which is not a pass and not a fail.
