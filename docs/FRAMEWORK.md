# Responsible Agentic AI Testing Framework v0.1

> **Test coverage, not a compliance determination.** This framework says which agentest tests provide evidence for which control. Passing them does not make a system conformant with any standard or law, and no percentage score is given.

The framework groups the 110 tests of the Agentic AI Test Checklist into four pillars. Every test sits in exactly one pillar, chosen by its catalogue `eval_group`, and every test ID below has a universal rule in agentest (`agentest std run` returns pass, fail or n/a for it). Control codes are taken only from the reviewed vocabulary in [`standards_map.yaml`](../src/agentest/standards/standards_map.yaml) (see [Standards map](standards/STANDARDS-MAP.md)).

Generated by `python scripts/gen_framework.py` (CI runs `--check`). The same data is machine-readable in [`coverage-map.json`](coverage-map.json). The 20 repo extensions (`X-001` to `X-020`) are not assigned to a pillar in v0.1.

## The four pillars

| Pillar | Question it answers | Tests | P0 | Catalogue groups |
|---|---|---|---|---|
| [Evals: task success and reliability](#evals) | Did the agent do the right thing, in the right order, every time? Terminal state, false completion, dependency order, idempotency, rollback, state across turns and consistency under paraphrase. | 39 | 14 | `functional`, `reliability_robustness`, `data_lineage` |
| [Security](#security) | Can untrusted content or a caller make the agent misuse its tools? Prompt injection, tool allowlists, argument validation, authorisation, approval tokens, delegation and secrets. | 43 | 24 | `security` |
| [Privacy](#privacy) | Does personal data stay where it belongs? Identity checks before disclosure, PII in tool arguments, tenant scoping, revoked consent, soft deletion and masking. | 8 | 5 | `privacy` |
| [Responsible behaviour](#responsible) | Does the agent act accountably and fairly? Human approval before irreversible actions, oversight gates, audit trails, explanations that match actions, and decisions that do not change with language or demographics. | 20 | 4 | `compliance_governance`, `explainability`, `bias_fairness` |

Total: 110 tests.

## How to use it

1. Pick the pillars that matter for your agent (evals and security together hold 82 of the 110 tests and 38 of the 47 P0 tests).
2. Run the P0 tests of those pillars in CI first; add P1 and P2 as your traces carry the needed signals.
3. Report results per pillar as tests run, passed, failed and n/a, and list the controls those tests map to. Say "coverage" (which tests map to a control), never "compliance".
