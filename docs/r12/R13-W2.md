# r13 version note — T1-001 state outcome (W2)

Unreleased. Not tagged, not merged, not published. Base line: `r12-core47`.

T1-001 now checks every run that publishes a task spec. Postconditions are recomputed from the recorded
`agentest.initial_state`, `agentest.final_state` and the spec's `{path, op, value}` predicates.

`effects.<object>.new_payouts`, `effects.<object>.paid_inr` and `effects.<object>.new_rejections` are computed
from the snapshot change. A payout or rejection record that is in the final collection and absent from the
initial one counts toward each subject id named by an `id` or `*_id` field on that record (or the record key,
when it names none). `paid_inr` is the amount on the new payout records. The collections are the generic
`payouts` and `rejections` maps, read from `output` when that object is present.

A path that is not one of those metrics and is not present in the final snapshot is unresolved. That cell is
not-assessed. An unresolved path is not a failure. A resolved value that misses its predicate still fails.

The harness attribute `agentest.postcondition.result` is compared afterwards. When it differs from a resolved
pass or fail, the verdict names the disagreement and still follows the recomputed state.

A run with no task spec is unchanged: the check still uses the first canonical success signal
(`gen_ai.evaluation.result`, or published postconditions in examples mode) and stays `n/a` when that signal
is absent.

The implementation is `src/agentest/standards/detectors/state_outcome.py`, reached by the T1-001 registry hook.
Contradictory terminal states (two successful state-changing calls on one object) are still failed before the
state-outcome pass.
